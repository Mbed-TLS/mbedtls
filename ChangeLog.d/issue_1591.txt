Security
   * Fix a client-authentication bypass in TLS servers that use SNI to support
     several virtual hosts with different client-authentication policies and
     use session resumption. When several virtual hosts share an SSL
     configuration and its session cache or ticket keys, a malicious client
     can establish a resumable session with a virtual host that does not
     require a client certificate, then resume that session with a different
     virtual host that requires client authentication. The resumed handshake
     does not enforce the stricter authentication policy, allowing
     unauthenticated access to the protected virtual host. This issue affects
     session ID-based resumption and session tickets.

     Servers with distinct client-authentication contexts must partition their
     resumption state. The new mbedtls_ssl_set_hs_session_cache_context() and
     mbedtls_ssl_set_hs_session_ticket_context() functions let an SNI callback
     select the appropriate session cache or ticket context for the current
     client-authentication context.

     Server applications must select, through the SNI callback, distinct
     contexts for virtual hosts with different authentication policies, or
     invalidate sessions when those policies change. Existing applications
     that continue to share resumption state between different authentication
     contexts remain vulnerable.

     Reported by Younghyo Cho, CIS Lab, Seoultech, and independently by Jaehun
     Lee, Pohang University of Science and Technology (POSTECH).
     CVE-2026-93776.
